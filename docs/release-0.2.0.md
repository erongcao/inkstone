# Inkstone v0.2.0 功能说明

> 发布日期：2026-10-29 ｜ 这是 Inkstone 的**首个正式版**（`0.1.0` 只在开发期用过，从未发布）
>
> 英文版：[docs/release-0.2.0.en.md](release-0.2.0.en.md) ｜ 变更记录：[CHANGELOG.md](../CHANGELOG.md) ｜ [English README](../README.en.md)

这一版把 AI 从「能改写、能总结」补到「**能问、能溯源**」，同时修好了三条导出链路上的不一致。

## 一、AI 问答模式（新增）

### 它是什么

在文档里问一个问题，Inkstone 先用 BM25 检索出最相关的几节，把它们编号后交给模型；模型的答案里带 `[n]` 引用，界面把**答案真的引用了**的那些来源列出来，点一下就跳回原文那一段。

### 链路

```
文档 → 按 ATX 标题切块（边界来自 mdast）
     → BM25 排序（零分不进结果，取前 5）
     → 拼成带编号来源的请求
     → 流式请求
     → 解析答案里的 [1] / [1,2] / [1-3]
     → 面板列出引用来源（点一下跳回原文那一段）
```

### 界面上看得见的三条规矩

AI 输出不确定，界面**不替它圆场**：

| 情况 | 界面说什么 |
| --- | --- |
| 检索不到相关内容 | 「文档里没有找到与这个问题相关的内容」——**不让模型空想** |
| 模型引用了不存在的序号 | 「第 N 号来源不存在」——**不假装有那一段** |
| 模型没标引用 | 来源区为空——**不替它编一个** |

### 两个设计决策（决定了它好不好用）

**1. 检索块 = 一节，不是「固定多少字」**

检索块同时是**引用溯源**的单位：面板上列出的每个来源，都要能说清「这句话出自哪一节」。
早先的实现把过短的块与相邻块合并，于是两节正文都不足 200 字时会并成一块，标题路径只留第一节——
面板上列出来的来源名与摘录**对不上**，用户点进去看到的也不是那一节。

现在：**只在一节内部**合并，跨节不合并。短节自己成块——检索层要的不是块大，是「块与问题的相关性」。

**2. 标题里的词也要能检索到**

正文不一定重复标题里的词。「# 安装」这一节正文写「打开终端，输入下面的命令」，
用户问「安装怎么操作」——如果只索引正文，一个词都对不上，检索会判成「文档里没有相关内容」。
那是**假阴性**：用户看到的是「没找到」，不是「没排第一」，比漏召回严重得多。

所以索引用的是「标题路径 + 正文」，而**给人看的正文仍然是纯正文**。

### 其它取舍

- **标题边界来自 mdast**（架构约束 C）：代码围栏里的 `# 注释`、引用块里的 `> # 标题`、列表项里的 `# 标题` 都不是章节——自己扫行找 `#` 会立刻踩这三个坑。
- **中文分词用字符 bigram**：零依赖、零词典。仓库里没有中文分词库，加依赖要过许可证白名单，而纯 JS 分词器动辄几百 KB。代价是「实现」和「行进」这类词会互相干扰——这是有意识的取舍：检索层只要把相关段落捞出来，精确分词交给模型自己。
- **零分块不进结果**：把一堆不相关的块塞给模型只会稀释上下文。

### 怎么验证

- 守卫：`tests/ai-retrieval.test.ts`（切块 / 分词 / BM25）、`tests/ai-qa.test.ts`（请求构造与引用解析）、`tests/ai-features.test.tsx`（面板与写回）
- 变异验红：把索引改回「只索引正文」→ 1 条守卫变红；把合并改回「跨节」→ 5 条守卫变红
- 真机实测（本机 Ollama / `qwen3.8:27b-mlx`）：

  ```
  切块：chunk-1 ["砚台"] / chunk-2 ["墨水"] / chunk-3 ["纸"]
  BM25：命中 chunk-1 ["砚台"] score=2.3100（其余零分不返回）
  请求：[1] 标题路径：砚台 + 该节正文（只有相关那一段）
  模型：砚台多为石材制成，讲究「下墨如漆」，常见的有歙砚与端砚。[1]
  解析：[1] → ["砚台"]
  ```

## 二、AI 端点管理（新增）

### 自建端点

设置面板里可以新建 / 编辑 / 删除自建端点（OpenAI 兼容协议 + 自定义 base URL），密钥存进**系统钥匙串**。

两条从数据结构推出来的规则：

- **端点 id 不许与内置端点重名**。端点 id 就是系统钥匙串里的 account 名，而端点解析是「自建优先于内置」——重名会让自建端点**静默接管**内置端点的密钥，删除自建端点时又顺手删掉内置密钥。后果发生在**别的**端点上，所以从数据结构上堵死，而不是提示一下。
- **端点 id 建好后不可改**。改名 = 换钥匙位置 = 旧位置剩下一个孤儿密钥，而那个孤儿**没有任何界面能删**（界面上已经没有这个端点了）。界面上只读显示，并写明原因。

删除端点时**一并**删掉钥匙串里的密钥、清掉它的模型覆盖、清掉它的模型列表——否则钥匙串里会留下一个没人能删的孤儿。

### 「测试连接」分情况报错

「连接失败」对用户没有任何信息量。现在一次探测能分清五种情况：

| 情况 | 判定 |
| --- | --- |
| 密钥不对 | 401 / 403 |
| 服务没有「列出模型」接口 | 列表接口 404，但聊天接口通 |
| 路径写错 | 列表接口与聊天接口**都** 404 |
| 限流 | 429 |
| 服务端错误 | 5xx |

难点是 **404 有两种含义**，一次探测分不开。解法是**两个探测**：先探列表接口（GET），404 时再探聊天接口（POST）——
聊天接口通 → 服务只是没有列表接口；两个都 404 → 路径不对。

聊天接口那次探测**会真的花掉 1 个 token**，也会出现在对方的调用记录里。这是有意的取舍：
不多花这一次，就分不清「服务不支持列模型」与「路径写错了」。

判定层写成**纯函数 + 可注入依赖**（`probe` / `parse`），所以 13 条守卫能不联网地覆盖每一种判定组合。

### 模型列表与换模型

- 列表挂在**模块级 store** 上，按端点 id 归属——关掉设置面板、切到别的端点再回来，列表还在。
- **AI 面板里就能换模型**，与设置面板**同源**（同一个 `modelOverrides`）。
- 顺带修掉一个真 bug：加载态原先拿**渲染快照**比对，列表加载完也清不掉——按钮会永久停在「正在获取模型列表…」且永久禁用。

## 三、导出链路修好三处

| 问题 | 以前 | 现在 |
| --- | --- | --- |
| Mermaid 图 | 屏幕上能渲染，导出里是一坨源码 | 导出渲染成 SVG；**渲染失败原样保留源码块**，不悄悄变空白 |
| GitHub 提示块 | pandoc 没有 alert 扩展，`> [!NOTE]` 原样输出 | 改写成「引用块 + 粗体标题」，每种 pandoc 输出格式都支持 |
| 没人引用的脚注定义 | remark 静默丢弃，pandoc 丢弃并告警 | 按原文**留在原处**，导出时提示「有 N 个脚注定义没有被引用」 |

细节：

- **Mermaid 排在代码高亮之后**。做法是让高亮**放过** `language-mermaid` 块（而不是先渲染再被高亮抹掉），这样渲染失败时的源码块逐字不变。Mermaid 仍然**懒加载**（主 chunk 无静态 import）。
- **提示块改写成「引用块 + 粗体标题」**，是因为引用块与粗体是每种 pandoc 输出格式都支持的两样东西。围栏 div 不行（DOCX 会摊平），重序列化 mdast 更不行（会重排用户的原文）。真 pandoc 验过：输出是 `<blockquote><p><strong>NOTE</strong></p><p>这是一条提示。</p></blockquote>`，嵌套 `>>` 也对。
- **脚注定义留在原处**，不挪到脚注区、不丢弃、不凭空编号。

## 四、PDF 真页码：为什么做不成

不是没做，是**当前这条链路上没有真办法**。逐条实测过：

1. **当前路径拿不到 PDF 文件**：`Webview::print()` → macOS 的 `WKWebView.printOperation:` → **系统打印面板**，
   用户自己选「存储为 PDF」。文件落在用户选的地方，**进程内没有它的句柄**。
   没有文件就没有「真实页数」可读，也没法盖章。
2. **Tauri 不给第二条路**：Tauri 2.12 的 `Webview` 只有 `pub fn print(&self)`，没有 `printToPDF` / `createPDF`。
3. **wry 也不给**：wry 0.57 在 macOS 上的 `print_with_options` 内部是
   `NSPrintInfo::sharedPrintInfo()` → 设 margin → `printOperationWithPrintInfo:` → `runOperation()`，
   **没有任何注入 save 路径的口子**。
4. **拿不到原生句柄**：wry 把 `InnerWebView` 声明成 `pub(crate)`，`tauri_runtime_wry::Webview` 也不往外暴露。
5. **绕开 Tauri 自己打印：分页跑飞**。Swift 原型实测（独立 `WKWebView` + `NSPrintOperation`，
   配 `NSSavePath` + `NSJobDisposition = NSPrintSaveJob` 直出文件）：
   **3 页的文档产出 96 万～175 万页**，文件 200–455 MB。
   而 `MediaBox` 是对的（`[0 0 595 842]`）、布局宽度也正常（595×842，body 338px）——
   说明**爆炸发生在打印操作内部**，不是页面尺寸设错了。

真页码的前提是「自己拥有 PDF 文件」，那意味着换一条能直出文件的渲染链路（自带 Chromium，或自己实现分页），
属于**换架构**的量级。所以：**不塞假的页码**（自己数页再猜，猜错了用户看不出来）。

## 五、其它已知限制

- **Windows / Linux 没有真机验证**：字体、输入法、原生菜单、钥匙串 libsecret 降级路径都只有 CI 层面的验证，没有人在真机上跑过。
- 「公式自动编号」开关仍**置灰**（代码里没有编号功能）。
- 「导出变量」只在导出产物上替换，**不进正文**。

## 六、怎么验证这一版

```bash
pnpm install
pnpm typecheck && pnpm lint && pnpm format:check && pnpm test
pnpm i18n:check && pnpm licenses:check
pnpm gen:shortcuts -- --check && pnpm gen:theme-tokens -- --check
cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test --lib
```

本版实测：前端 **1721 通过 / 1 跳过**，Rust **105 通过**；CI 九个 job 全绿（Rust 检查、许可证白名单、前端 Node 22 / 24、三平台打包）。

**round-trip 测试是本项目最重要的质量基建**：13 份真实 Markdown 语料，每次提交都跑「解析 → 序列化 → 再解析 → 结构等价」断言。
没有它，Live Preview 会慢慢腐蚀用户文件。
